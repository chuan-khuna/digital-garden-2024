## Overview

When you share a link on LINE, X, Facebook or Slack, the platform shows a preview image: the Open Graph (OG) image. This site generates one for every post at build time, from a React component:

```
React component → Satori (SVG) → Sharp (PNG) → /og/posts/<id>.png
```

This post walks through the smallest version that works, then shows how this site organises the same idea.

## A simple example

Three pieces: a function that renders the image, a route that emits one PNG per post, and a `<meta>` tag that points to it.

### 1. Render a PNG

```tsx
// src/lib/render-og-image.tsx
import satori from 'satori'
import sharp from 'sharp'
import fs from 'node:fs/promises'

const font = await fs.readFile('./src/assets/fonts/VictorMono-Regular.ttf')

export async function renderOgImage(title: string, description: string) {
  const svg = await satori(
    <div
      style={{
        width: '100%',
        height: '100%',
        display: 'flex',
        flexDirection: 'column',
        justifyContent: 'center',
        padding: '80px',
        backgroundColor: '#f7f8f9',
      }}
    >
      <h1 style={{ fontSize: '64px' }}>{title}</h1>
      <p style={{ fontSize: '32px' }}>{description}</p>
    </div>,
    {
      width: 1200,
      height: 630,
      fonts: [{ name: 'VictorMono', data: font, weight: 400 }],
    },
  )
  return sharp(Buffer.from(svg)).png().toBuffer()
}
```

Satori only understands **inline styles** and a subset of Flexbox. No CSS classes, no Tailwind.

### 2. One route, one PNG per post

```typescript
// src/pages/og/posts/[...slug].png.ts
import type { APIContext } from 'astro'
import { getCollection } from 'astro:content'
import { renderOgImage } from '@/lib/render-og-image'

export const prerender = true

export async function getStaticPaths() {
  const posts = await getCollection('posts')
  return posts.map((post) => ({
    params: { slug: post.id },
    props: { post },
  }))
}

export async function GET({ props }: APIContext) {
  const { title, description = '' } = props.post.data
  const png = await renderOgImage(title, description)
  return new Response(png, { headers: { 'Content-Type': 'image/png' } })
}
```

`prerender = true` makes Astro call `GET` once per path at build time and write the PNGs into `dist/`, so there is no image work at request time.

### 3. Point the page at it

```astro
---
// src/pages/posts/[...slug].astro
const ogImage = new URL(`og/posts/${Astro.params.slug}.png`, Astro.site)
---

<meta property="og:image" content={ogImage} />
<meta property="twitter:card" content="summary_large_image" />
```

That's all it takes. Run `bun run dev` and open `http://localhost:4321/og/posts/<your-post>.png` to see the image.

## How this site does it

The simple example has two weak spots once a site grows:

- **Pages build the image URL themselves.** If a page asks for a URL that no route generates (a typo in a slug), the build still passes and the preview is silently missing.
- **Styles are strings.** Pick a style name that has no theme and you quietly get the default.

So this site puts everything behind one module, `src/lib/og-image/`:

```typescript
// in a page
import { pageOgImage, articleOgImage } from '@/lib/og-image'
const ogImageUrl = await pageOgImage('resume') // fails the build if 'resume' isn't configured
const postImageUrl = articleOgImage('posts', Astro.params.slug!)

// in an OG route
return ogImageResponse(article.data) // renders + wraps the PNG in a Response
```

- **Posts and notes** get `/og/<collection>/<id>.png` from their frontmatter:

  ```yaml
  ---
  title: My Post
  description: Post description for social media
  ogStyle: 'particle' # 'default' | 'default-dark' | 'particle'
  ---
  ```

- **Ordinary pages** (home, resume, uses) are customised in `src/content/og-images.json`: one entry per page with its own title, description and style. `{{siteTitle}}` in a title is filled in at build time.

  ```json
  {
    "slug": "uses",
    "title": "Uses",
    "description": "The items/tools I am using",
    "ogStyle": "particle"
  }
  ```

- **Styles are typed.** The style list is a Zod enum, and the theme map is `Record<OgStyle, Theme>`. Add a style without a theme and TypeScript refuses to compile. Put an unknown `ogStyle` in frontmatter and the content schema rejects it.

The pure parts (URL shape, the page-slug check, `{{siteTitle}}`) are unit-tested with Vitest. The rendering itself is checked by the build.

## Tips

- Keep text inside the 1200×630 canvas: truncate long titles and shrink the font size for long ones.
- Load fonts once at module level. Satori needs the raw font file (`.ttf`/`.otf`), not `.woff2`.
- Check the result with the [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) or [LinkedIn Post Inspector](https://www.linkedin.com/post-inspector/).
