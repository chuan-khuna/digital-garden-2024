Warm paper, careful type.

The design system for the garden's web pages. The colours are the site's own presets (nzk, dark, nexus) and stay exactly as they are. This page defines how they're used: which role each colour plays, how type carries the hierarchy, and how little the interface needs to move.

Preview in

Principles

Colour comes from the presets
The system adds no colour values. It gives the existing preset variables role names, so switching between nzk, dark and nexus re-themes every component.
Lines, not boxes
Hierarchy comes from 1px rules and whitespace. No drop shadows, and no filled panels behind reading text.
Type does the emphasis
DM Serif Display for titles, Lato for everything else. Headings stay upright. Emphasis comes from weight or colour.
Each colour has one job
Indigo for actions and headings, teal for links, orange for "you are here". There's never more than one orange mark in view.
Motion answers the hand
Nothing moves on its own. Hover and press get quick colour changes and a 1–2px nudge at most.

Motion

Colour changes do almost all the work. Only transform and colour properties animate, and nothing moves unless the reader touches it.

ElementResponseTiming
ButtonBackground lightens on hover and the button drops 1px on press--dg-dur-fast · --dg-ease-out
Linked cardBorder darkens and the arrow moves 2px--dg-dur-fast
List row, linkUnderline fades in orange--dg-dur-fast
Preset switchBackground and text crossfade--dg-dur-base
Focus ringAppears instantly0ms
Everything elseNone. No scroll reveals, no idle animation.—

With prefers-reduced-motion: reduce, transitions become instant and nothing translates.

The print fence

The Resume and CV Print Pages must render exactly as they do today. BaseLayoutPrint.astro imports the same globals.css as the web layouts, and the theme toggle sets data-color-preset on the print page too. So the system must never edit anything those pages read.

Frozen: do not edit

  • src/styles/presets/*.css and the :root values in globals.css. These are the colour source for both web and print.
  • src/layouts/BaseLayoutPrint.astro, src/styles/print.css
  • src/pages/resume-print/**, src/pages/cv-print/**
  • src/components/resume/**. The sections are shared with the web resume.
  • tailwind.config.ts fontFamily: sans, serif, mono, metric, canela, resumesans, resumeserif

Why the system can't leak

  • It defines no colour values, only --dg-* names that read the preset variables
  • Those names are declared under [data-surface="web"], set on <body> in BaseLayout.astro only (PostLayout wraps it)
  • Components use .dg-* classes, which print markup never has
  • The web /resume is restyled only through WebWrapper.astro

Proving it didn't change

  1. Snapshot before

    On main: bun run build && bun run preview, then print /resume-print/, /cv-print/ and each Resume Version with headless Chrome (--print-to-pdf --no-pdf-header-footer).

  2. Snapshot after

    The same pages on the adoption branch, with the same Chrome.

  3. Compare pixels

    pdftoppm -r 150 -png, then magick compare -metric AE page by page. Anything above 0 blocks the merge.

  4. Check the frozen paths

    git diff --stat main -- src/styles/presets src/layouts/BaseLayoutPrint.astro src/styles/print.css src/components/resume src/pages/resume-print src/pages/cv-print prints nothing.

Adopting it

One new stylesheet of role names, one attribute on one layout. Most roles already have a Tailwind utility (bg-background, border-border, text-primary), so only the mixed ones need new keys.

src/styles/system.css

Imported in globals.css after the presets.

Order of work

  1. Take the print snapshot first

    Before any code change, so there's a baseline.

  2. Add the roles and the attribute

    Nothing looks different yet. Components opt in one by one.

  3. One component per commit

    Nav → bento card → post index → tags → callouts and code. Check each in all three presets at 320, 375, 414 and 768px.

  4. Update the docs

    Point docs/architecture/add-theme.md here. A new preset only needs to supply the same variables; the roles follow.
