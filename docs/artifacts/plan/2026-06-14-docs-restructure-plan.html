Refactor Plan · Digital Garden 2024

Flatten .vault/ into docs/ & replace skills with two agents

Collapse the nested Obsidian vault and the two project-skills into a single, flat docs/<category>/ knowledge base — then wire that knowledge into two purpose-built subagents: developer and web-master.

scope: docs migration 2 agents 5 doc categories non-breaking to src/

01What we're solving

Three sources of truth exist today, each with its own nesting and tooling overhead:

  • .vault/astro-knowledge/ — an Obsidian vault and a nested git repo, carrying .obsidian/, .git/, .claude/, .agents/ and skills-lock.json just to hold ~15 markdown notes.
  • project-skills/manage-content/ — a skill + 7 reference docs describing content/collection formats.
  • project-skills/add-theme/ — a skill describing the 4-file theme-add procedure.

The goal: one plain-markdown docs/ tree as the knowledge source, and the procedural parts of the skills promoted into two invokable agents that read from that tree.

05The two agents

Skills auto-trigger on description match; agents are explicitly invoked and carry a focused remit. Each agent's SKILL.md body becomes its system prompt, pointing at the relevant docs/ folders as its knowledge base. Stored as markdown in .claude/agents/.

developer

Builds & authors

Owns data, schema, content & system code. Absorbs the manage-content skill.

  • Add / edit posts, notes, resume, nav entries
  • Change collection-definition schemas and keep docs/content/ in sync (the old schema-sync rule)
  • Markdown pipeline, bidirectional links, deployment, project structure
  • Site & portfolio config data

Reads: docs/architecture/, docs/content/

Tools: Read, Edit, Write, Grep, Glob, Bash

web-master

Themes & visual layer

Owns styling, themes & visual presentation. Absorbs the add-theme skill.

  • Add / edit themes — CSS presets, global.css import, ThemeToggle.astro wiring, syntax-highlighter map
  • OG image styling, bento homepage layout
  • Tailwind v4 + oklch token conventions, design polish
  • Enforces the 4-file theme checklist

Reads: docs/theming/, docs/architecture/{og-image-generator,bento-grid}.md

Tools: Read, Edit, Write, Grep, Glob

Boundary rule: where content and visuals overlap (OG images, portfolio) — developer owns the data/schema, web-master owns the CSS/render. Write this line into both agent prompts so they hand off cleanly.

07Migration steps

  1. Scaffold docs/ with the five category folders. No deletes yet.
  2. Copy + rename vault notes into architecture/, theming/, artifacts/, notes/ (kebab-case, strip [[wikilink]] syntax → relative md links).
  3. Copy manage-content/references/* → docs/content/; merge how-to-manage-themes.md into docs/theming/themes-reference.md.
  4. Author docs/theming/add-theme.md from the add-theme SKILL body; write docs/README.md index.
  5. Write agents — .claude/agents/developer.md & web-master.md with frontmatter (name, description, tools) + system prompt pointing at their docs/ folders.
  6. Patch CLAUDE.md (the three edits in §06).
  7. Delete .vault/ and project-skills/ once the new tree is verified.
  8. Verify — bun run dev still builds (these are docs-only, no src/ import touches them), and both agents resolve their doc paths.
