1 · Deepen the Print Layout module

Strong in-process
  • src/components/resume/pages/ResumePrintPage.astro (302 lines: frontmatter, markup ×3, inline script)
  • src/content/collection-definitions/resume-sections.ts (Section registry, "not wired in yet")

Before — one concept, five places

frontmatter layouts[], sections[]
markup · 3 layouts 18× data-section
attr string data-default-hide
inline script · ~85 lines 0 tests
Section registry unused

After — one deep module, two thin adapters

Print Layout module

· Print Layouts: name, Surface, arrangement

· default-hidden Sections

· selection rules (URL ⇄ state)

· Section names from the registry

page markup

loops the layouts

browser script

sets hidden / aria-pressed

Vitest crosses the same interface

Problem. The Print Layout concept — names, which Surface, which Sections show by default, how ?layout=/?hide= resolve — is spread over frontmatter, 18 hand-repeated data-section wrappers, an attribute string and an untested inline script; a typo in any one silently breaks a toggle.

Solution. Hold every Print Layout and the selection rules in one TypeScript module that both the page markup and the browser script import, with Section names taken from the existing Section registry.

  • locality: add a layout in one place
  • leverage: markup and script share one interface
  • selection rules gain Vitest tests
  • Section registry finally earns its keep
  • Surface per layout becomes explicit data
  • script shrinks to a DOM adapter

2 · Let the Print Page resolve its own Surfaces

Worth exploring in-process
  • src/pages/resume-print/index.astro
  • src/pages/resume-print/[version].astro
  • src/components/resume/pages/ResumePrintPage.astro (props: resume, cv, noindex)
  • src/lib/resume/index.ts

Before

flowchart TB
  I[index.astro] -->|resume_print| G[getResume]
  I -->|cv_print| G
  V["[version].astro"] -->|resume_print| G
  V -->|cv_print| G
  I -->|"resume, cv"| P[ResumePrintPage]
  V -->|"resume, cv, noindex"| P
  classDef leak stroke:#dc2626,stroke-width:2px,color:#991b1b;
  class I,V leak

After

flowchart TB
  I[index.astro] -->|version| P[Print Page]
  V["[version].astro"] -->|version| P
  P --> G[getResume per Surface]
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a,stroke-width:3px;
  class P deep

Problem. Each route must know which Surface feeds which prop (resume_print → resume, cv_print → cv) and that noindex means "not the Default Version"; both routes repeat it, and a swapped prop type-checks fine.

Solution. The Print Page takes only a Resume Version and derives both Surfaces and noindex itself; routes shrink to "which version".

  • interface shrinks to one input
  • Surface knowledge stops leaking into routes
  • noindex rule lives in one place
  • pairs naturally with candidate 1

Speculative in-process
  • src/components/resume/layout/Content.astro (11 lines: a div with className)

After — three bands, each earning its keep

Problem. Content's interface (className + slot) is its whole implementation; the deletion test shows complexity vanishes rather than moving.

Solution. Replace it with plain divs; keep WebWrapper and PageLayout, which hide real behaviour.

  • one fewer shallow module to read
  • layout grid visible where it's used
  • tiny change; low payoff
