Adapter: getCollection → {id, title, aliases, body}[]. Tests pass fixture arrays.

Problem. The rendered link and the backlink panel use different resolution rules, so [[Zettelkasten]] in zettelkasten-note-types renders as a 404 and nothing reports it. The backlink module reads every post from disk on every page (O(N²)), ignores notes, and its regex matches examples inside code fences.

Solution. A pure link-graph module built once from content entries. The remark plugin's resolver, the posts page and the backlink panel all query it.

  • Locality: one resolution rule
  • Broken links fail the build
  • Removes the fs path-guessing
  • First real garden test surface
  • Deletes 3 copies of the match logic

Caveat: the remark plugin runs at markdown-processing time, before getCollection is available. The graph's adapter for remark may need to read the post index itself (glob + frontmatter). That is a second adapter, which confirms the seam is real.

Top recommendation

1 · Deepen the wiki-link graph into one module

Bidirectional links are the core of the garden, and today the rendered link and the backlink panel disagree. The result is a live 404 that nothing reports. One pure link-graph module fixes the bug, removes the O(N²) disk reads, and gives the garden its first test surface.
